# ميد أوربت | MedOrbit

تطبيق عربي تجريبي لإدارة دليل الأطباء والمنتجات الخيالية وتقارير الزيارات المهنية، أُنشئ للهاكاثون الجامعي.

## ما الذي يعمل؟

- دليل أطباء قابل للبحث والتصفية، مع إضافة وتعديل وملف لكل طبيب.
- حقول الاسم والاختصاص والمنطقة والعنوان والإحداثيات التقريبية وأوقات استقبال المندوبين والاهتمامات العلمية.
- ثلاثة أطباء أساسيين وستة أطباء إضافيين للجولة، وثلاثة منتجات خيالية للعرض، تُضاف مرة واحدة دون استبدال التعديلات.
- نموذج تقرير زيارة مرتبط بطبيب ومنتج محفوظين، مع النتيجة والملاحظات المهنية والتاريخ.
- تأكيد الزيارة برمز تجريبي من ستة أرقام قبل حفظ تقرير جديد؛ وصفحة محاكاة سكرتير منفصلة.
- سجل تقارير ولوحة شركة تستعلم قاعدة البيانات فعليًا؛ لا توجد أرقام أداء مُختلقة.
- واجهة عربية من اليمين إلى اليسار، للهاتف والكمبيوتر.
- مخطّط جولة تقريبي `/smart-route` حسب المنطقة ونقطة انطلاق تجريبية ووقت البداية والسرعة ومدة الزيارة، مع الانتظار وترتيب الزيارات وأسباب الاستبعاد.

## الخصوصية وحدود هذه المرحلة

هذه نسخة هاكاثون مفتوحة بلا تسجيل دخول أو فصل للصلاحيات، وليست نظامًا طبيًا أو نظام شركة جاهزًا للاستخدام الحقيقي. استخدم بيانات خيالية فقط.
لا تُدخل معلومات مرضى أو أرقام هواتف حقيقية أو صور وصفات أو سمات شخصية حساسة في أي حقل، بما فيه الملاحظات.
الرمز التجريبي لا يثبت الحضور الفعلي. لا توجد رسائل SMS أو واتساب أو خدمات مراسلة، ولا موجز ذكاء اصطناعي أو صيدليات. مخطّط الجولة تقدير جغرافي وليس ملاحة طرق أو حركة مرور حية.
المنتجات خيالية بالكامل ولا تمثل أدوية ولا تُقدم توصيات علاجية.

## البنية

تطبيق واحد في مستودع واحد: واجهة React وTailwind، وخادم Node.js/Express واحد وقاعدة PostgreSQL دائمة، وليست خدمات مصغرة.

- `artifacts/medorbit` — الواجهة.
- `artifacts/api-server` — جميع واجهات الخادم.
- `lib/db` — مخطط قاعدة البيانات واتصالها.
- `lib/api-spec/openapi.yaml` — عقد الواجهات البرمجية.
- `lib/api-client-react` و`lib/api-zod` — العميل والتحقق المولّدان من العقد.

## التشغيل في Replit

شغّل التطبيق من المعاينة. خادما الواجهة والـAPI مُعرّفان مسبقًا.
تُدار قيمتا `DATABASE_URL` و`SESSION_SECRET` سرّيًا بواسطة البيئة، ولا توجد أسرار ضمن هذا المستودع أو ملف التنزيل. يلزم سر جلسة ثابت بطول 16 محرفًا على الأقل؛ لا تغيّره بين التشغيلات لأنه يحمي البصمات والتشفير.

```sh
pnpm install --frozen-lockfile
pnpm --filter @workspace/db run push
pnpm run typecheck
```

ثم شغّل مساري التشغيل المعرّفين للمشروع:

- `pnpm --filter @workspace/api-server run dev`
- `pnpm --filter @workspace/medorbit run dev`

في Replit، مسارات التشغيل المُدارة توفّر إعدادات المنافذ والمسار تلقائيًا. لتشغيل نسخة خارج Replit، تحتاج PostgreSQL وقيمتي `DATABASE_URL` و`SESSION_SECRET` آمنتين، ومنفذًا للخادم، و`PORT` و`BASE_PATH=/` للواجهة، ووكيلًا واحدًا يوجّه `/api` للخادم وبقية المسارات للواجهة. لا تنقل قاعدة البيانات أو الأسرار عبر Git.

تُطبق تغييرات المخطط على قاعدة التطوير باستخدام الأمر `push` أعلاه. نشر Replit يدير ترحيل مخطط قاعدة الإنتاج؛ لا يوجد إنشاء جداول تلقائي عند بدء الخادم. بدء الخادم يضيف البيانات الخيالية المفقودة فقط.

## التحقق

اختبار الجولة الحالية: خذ لقطة مقارنة قبل الاختبار، ثم شغّل فحص الجولات ضد خادم التطوير العامل:

```sh
node scripts/verify-smart-route.mjs --snapshot
node scripts/verify-smart-route.mjs
```

للتأكد من سلامة إضافة الأطباء في بداية التشغيل، يمكن أخذ اللقطة أولًا ثم إعادة تشغيل خادم API ثم تشغيل الفحص. ستُقارن السجلات السابقة بينما تبقى الأطباء الستة الجدد إضافة مقصودة. راجع `docs/نتائج-اختبارات-الجولة.md` لنتائج 09:00 و11:30 و16:00 وحدود الحساب.

اختبار النسخة الحالية، بما فيها التحقق وحدود المحاولات وانتهاء الصلاحية وسلامة الميزات السابقة:

```sh
node scripts/verify-visit-otp.mjs
```

هذا الاختبار مخصص **لقاعدة التطوير فقط**. ينشئ بيانات خيالية خاصة به ثم ينظّفها، ويقارن السجلات السابقة للتأكد من عدم تغييرها. اختبار الانتهاء يضع موعد انتهاء سجل الاختبار في الماضي مباشرة داخل قاعدة التطوير، ولا يضيف منفذ تجاوز إلى التطبيق. النتائج في `docs/نتائج-اختبارات-رمز-العيادة.md`.

اختبارات التأسيس الأقدم مُوثّقة تاريخيًا في `docs/نتائج-الاختبارات.md`. اختبارها اليدوي عبر API أصبح يمر كذلك بخطوة التأكيد الجديدة:

```sh
node scripts/verify-medorbit.mjs
# أعد تشغيل خادم API ثم:
node scripts/verify-medorbit.mjs --after-restart
```

الاختبارات تنشئ سجلات خيالية مؤقتة؛ معرّفاتها تُكتب في `generated-artifacts/verification-state.json` لتُنظَّف من قاعدة التطوير بعد التحقق. لا تستخدمها مع قاعدة الإنتاج. ليست اختبارات متصفح آلية.

## عرض بشاشتين

1. شاشة المندوب: افتح `/visits/new`، اختر الطبيب، ثم «بدء زيارة معلّقة». لا يظهر الرمز هنا.
2. افتح رابط «صفحة محاكاة السكرتير» في تبويب ثانٍ، أو افتح `/clinic-demo` على شاشة أخرى لنفس التطبيق. اضغط «بدء محاكاة السكرتير» واختر الطبيب، ثم طابق مرجع الزيارة والمندوب.
3. انقل الرمز يدويًا إلى شاشة المندوب خلال خمس دقائق. بعد التأكيد، أكمل التقرير واحفظه. تظهر الحالة `Confirmed by clinic demo code`.

أي شخص يستطيع تفعيل محاكي السكرتير؛ هذه **محاكاة DEMO معلنة وليست صلاحية موظف حقيقية**. هوية المندوب جلسة تجريبية عشوائية يحددها الخادم، وليست حسابًا موثقًا. يمكن عرض التبويبين جنبًا إلى جنب ولا تُرسل أي رسالة.

## كيفية حفظ الرمز

- يُولَّد على الخادم بمولّد عشوائي آمن، مع الاحتفاظ بالأصفار في بدايته.
- التحقق ببصمة HMAC-SHA256 مرتبطة بمعرّف الزيارة والطبيب وجلسة المندوب. لا يُحفظ الرمز كنص صريح.
- لأن صفحة السكرتير تحتاج عرض الرمز بعد إعادة التحميل، يوجد أيضًا غلاف تسليم مشفّر بـ AES-256-GCM، بمفتاح مختلف مشتق من السر نفسه وسياق مرتبط بالزيارة. فكّه متاح فقط لمسار المحاكي بعد تفعيل جلسة السكرتير.
- تُحذف البصمة والغلاف عند النجاح أو الإقفال أو الاستبدال؛ تُمسح الرموز المنتهية عند الوصول لمسارات الحالة/المحاكي أو محاولة التحقق. الانتهاء والتحقق لا يعتمدان على عداد الواجهة.
- مهلة خمس دقائق، وخمس محاولات خاطئة، واستهلاك لمرة واحدة، وقفل صف قاعدة البيانات أثناء التحقق والحفظ لمنع السباقات.
- التأكيد يجيز تقريرًا واحدًا لنفس الطبيب والمندوب والزيارة. السجلات القديمة تبقى غير مُتحقَّق منها ولا تُعاد تسميتها على أنها مؤكدة.

## تجربة الجولة

افتح «الجولة» من قائمة التطبيق، ثم اختر «منطقة الجولة التجريبية» ونقطة الانطلاق الجنوبية. اترك مدة الزيارة 15 دقيقة والسرعة 25 كم/ساعة، وقارن أوقات البدء 09:00 و11:30 و16:00.

- المسافة الجغرافية بمعادلة هافرسين، وزمن الانتقال يقرّب لأعلى دقيقة. ليست مسافة طرق فعلية ولا تشمل ازدحامًا.
- ينتظر المخطّط فتح نافذة الاستقبال، ويشترط انتهاء كامل الزيارة بحلول الإغلاق.
- الاختيار جشع بنظرة قصيرة للأمام يفضّل المرشحين الذين يتركون زيارات ممكنة أكثر، ثم أقل وقت انتقال وانتظار ومسافة. لا يضمن أكبر عدد زيارات أو حلًا أمثل عالميًا.
- أوقات يوم واحد محلية، دون عودة لنقطة البداية، وبحد 100 طبيب في المنطقة. لا استراحات أو مواعيد محجوزة أو نوافذ ليلية.
- الحساب مؤقت للقراءة فقط. أعد الحساب بعد تعديل المدخلات أو ملفات الأطباء؛ إعادة تحميل الصفحة تزيل الاقتراح، ولا تحذف أي بيانات محفوظة.
- رابط «فتح تقرير زيارة» يفتح النموذج الحالي فقط؛ يبقى تأكيد OTP إلزاميًا قبل الحفظ.
