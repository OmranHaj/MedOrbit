# خريطة الأطباء التفاعلية

إضافة داخل MedOrbit الحالي، لا مشروع جديد ولا إعادة تصميم. لم يُغيّر مخطط قاعدة البيانات أو ملفات الأطباء والزيارات لإضافة الخريطة.

## ما نُفّذ

- `/doctor-map`: خريطة حقيقية قابلة للتقريب والتحريك عبر **React Leaflet5 وLeaflet1.9.4**.
- بلاطات HTTPS من `tile.openstreetmap.org` مع نسبة OpenStreetMap وLeaflet. لا مفتاح Google أو خدمة مدفوعة.
- `GET /api/doctor-map` يقرأ جدول الأطباء الحالي في PostgreSQL عبر Drizzle. يُرجع المعرّف الحقيقي والاسم والاختصاص والمنطقة والعنوان والإحداثيات وأوقات الاستقبال فقط.
- إحداثيات غير صالحة تُعرض كقيمةNULL في الاستجابة وقائمة **«الموقع غير محدد»**؛ لا تُصلح أو تُكتب فوق السجل. قيمة0 إحداثية فعلية وليست بديلًا عن نقص الموقع.
- البحث بالاسم، وتصفية المنطقة والاختصاص، والتبديل بين الجميع والمحددين للجولة، وعدّ العلامات والمواقع الناقصة.
- نافذة العلامة تعرض الملف والعنوان وأوقات الاستقبال، وتفتح ملف الطبيب بمعرّفه الحقيقي أو تضيفه للاختيار. أوقات ناقصة أو غير صالحة تمنع إضافته للجولة، دون منع عرضه أو فتح ملفه.
- رابط **«عرض على الخريطة»** من الملف يركز على عيادته ويميّز العلامة ويفتح نافذتها. في حالة موقع ناقص تظهر عبارة «لم يتم تحديد موقع العيادة بعد.»
- حالات تحميل وفشل بيانات، وفشل تحميل مكون الخريطة، وفشل البلاطات مع إعادة المحاولة؛ قائمة الأطباء والفلاتر لا تعتمد على نجاح تحميل البلاطات.
- حفظ أرقام الأطباء المختارين في `sessionStorage` لهذه التبويبة، دون ملاحظات أو رموز أو معلومات مرضى. **النتيجة المحسوبة مؤقتة في الذاكرة وليست جولة محفوظة بقاعدة البيانات.**

## الاتصال بمخطط الجولة

استُخدم **مخطط Smart Route الحالي على الخادم**، لا حساب مختلف داخل الخريطة:

- الطلب السابق بلا `doctorIds` يظل جولة جشعة لكل أطباء المنطقة، بالمدخلات والقيود السابقة.
- الاختيار يرسل معرّفات الأطباء فقط؛ الخادم يقرأ إحداثياتهم وأوقاتهم المحفوظة. يرفض التكرار والمعرّفات غير الموجودة واختلاط المناطق والحقول غير المصرح بها.
- خيار الترتيب اليدوي `preserveSelectionOrder` يحترم ترتيب المعرفات، لكنه يعيد حساب هافرسين والانتقال والانتظار ونوافذ الاستقبال على الخادم. الطبيب غير الممكن يُستبعد بسبب معلن، ولا يُنقل سرًا لموضع آخر لتجميل النتيجة.
- الأسهم في قائمة الاختيار تفعّل الترتيب اليدوي. بعد تغيير الاختيار أو المدخلات أعد الحساب؛ لا تُعاد تسمية العلامات دون حساب جديد.
- الأرقام من ترتيب المحطات في استجابة الخادم، وأوقات الوصول وبدء الزيارة والمغادرة هي نفسها في الجدول والنافذة.
- الخط يصل نقطة البداية التجريبية والمحطات وفق النتيجة. إذا أخفت التصفية إحدى المحطات يختفي الخط كاملًا مع توضيح، لا خط جزئي مضلل.
- عند تغير بيانات المواقع أو الأوقات يُخفى المسار القديم ويُطلب الحساب مجددًا. الحفظ في ملف طبيب أو تبديل منظور المندوب يبطل النتيجة المشتركة. استجابة حساب متأخرة بعد مغادرة الصفحة أو تغيير المدخلات لا تعيد نشر نتيجة قديمة.

**المسار المعروض تقريبي ولا يمثل طرق القيادة الفعلية.**

السرعة مفترضة وثابتة، لا ازدحام أو طرق قيادة أو GPS أو ادعاء حل أمثل عالميًا. الخريطة لا تثبت وجود مندوب فعليًا ولا سلوك وصف طبيب.

## عرض الميزة أمام لجنة التحكيم

1. افتح «خريطة الأطباء» من التنقل الحالي. جرّب التقريب والسحب ثم البحث باسم محفوظ وتصفية منطقة واختصاص.
2. افتح علامة ثم «عرض ملف الطبيب». من الملف اضغط «عرض على الخريطة» لمشاهدة التركيز على العلامة الصحيحة.
3. أضف طبيبَين أو أكثر **من المنطقة نفسها** إلى الجولة، ثم افتح مخطط الجولة. تُختار منطقة أول طبيب تلقائيًا.
4. احسب عند09:00، بمدة15 دقيقة وسرعة مفترضة25كم/س. راجع الجدول والعلامات وأوقات الوصول والمغادرة المتطابقة.
5. حرّك طبيبًا في القائمة وأعد الحساب. راقب الترتيب والأوقات وأسباب الاستبعاد إن صارت نافذة غير ممكنة.
6. افتح الخريطة من رابط الجولة، وبدّل إلى المحددين. تصفية تخفي محطة تخفي الخط وتعرض التوضيح.
7. أعد تحميل الصفحة: يبقى الأطباء المحفوظون واختيار هذه التبويبة، **لكن يلزم حساب جديد للنتيجة**. لم يُنشأ تقرير أو حجز أو رمز بمجرد التخطيط.

```sh

node --test generated-artifacts/doctor-map-unit.mjs
node scripts/verify-doctor-map.mjs
```

## فحص المتصفح الفعلي

| المطلوب | ما نُفّذ فعلًا |
|---|---|
| 1. خريطة تفاعلية | نجح تحميل بلاطات OSM الحقيقية بحجم256 بكسل، والتقريب والسحب على الكمبيوتر والهاتف. |
| 2. علامات من سجلات محفوظة | ظهرت السجلات التسعة الأصلية، ثم11 أثناء إضافة طبيبَي اختبار خياليين، دون مواقع مزروعة بديلة. |
| 3. البحث باسم طبيب | نجح حصر طبيب واحد، ونتيجة فارغة صريحة بلا علامات لبحث غير مطابق. |
| 4. تصفية المنطقة | نجح حصر منطقة الاختبار في طبيبَين؛ نجح أيضًا مرشح الاختصاص والتبديل إلى المحددين. |
| 5. العلامة إلى الملف | ظهرت حقول العيادة الحقيقية وانتقل الرابط إلى ملف معرّف الطبيب نفسه. |
| 6. الإضافة إلى الجولة | نجح اختيار الطبيبَين وبقاؤهما في الاختيار المشترك مع المخطط. |
| 7. حساب الجولة وعلاماتها | أُرسل طلب حساب حقيقي؛ تطابقت أوقات الجدول والنوافذ مع الاستجابة، وظهرت علامات مرتبة وخط فعلي. |
| 8. تغيير الترتيب | نُقل الطبيب الثاني للأعلى وفُعّل الوضع اليدوي؛ بعد إعادة الحساب تغير ترتيب طلب الخادم والجدول والعلامات والأوقات. النتيجة القديمة تصبح غير صالحة قبل الحساب. |
| 9. الملف إلى الخريطة | نجح التركيز وفتح نافذة الطبيب الصحيح. لا تُجبر علامة الطبيب المركّز على الظهور إذا أخفته فلاتر لاحقة؛ ظهر التنبيه وعدد مطابق. |
| 10. الهاتف والكمبيوتر | اختُبر1366×900 و360×800. عُثر أولًا على تجاوز أفقي وأُصلح، ثم قيس عرض التمرير مساويًا لعرض المحتوى345 بكسل. نجحت إصابة أزرار النافذة بارتفاع44 بكسل، وظهرت روابط التنقل التسعة ضمن الحدود. |
| 11. إعادة التحميل | أعاد الخادم11 سجلًا محفوظًا أثناء الاختبار وبقي اختيار الطبيبَين في التبويبة. اختفت نتيجة الجولة والخط كما هو معلن لأنها في الذاكرة فقط. |
| 12. الوحدات السابقة | نجحت فحوص API السابقة: OTP والتقارير واللوحة18، التحضير9، الصيدليات13، الجولة16، تسليم المنطقة12. لم يُعد تسلسل OTP على شاشتين في المتصفح ضمن اختبار الخريطة. |

اختُبرت حالات الخطأ التالية **باعتراض استجابات المتصفح فقط، لا بتخريب قاعدة البيانات**:

- منع طلبات البلاطات أظهر رسالة عربية وأبقى القائمة قابلة للاستخدام؛ إزالة المنع وإعادة المحاولة أعادا البلاطات الحقيقية.
- استجابة API500 أظهرت الخطأ وإعادة المحاولة، ثم استعادت البيانات الفعلية.
- استجابة `[]` أظهرت «لا يوجد أطباء محفوظون» ثم عادت السجلات بعد رفع الاعتراض. لم تُفرّغ القاعدة.
- نسخة استجابة بإحداثيات ناقصة نقلت الطبيب إلى «الموقع غير محدد» بلا علامة أو إحداثيات مخترعة.
- نسخة بلا ساعات زيارة أظهرت التنبيه وعطلت الإضافة إلى الجولة، ولم تعدّل الساعات المخزنة.
- منع تحميل وحدة الخريطة الديناميكية أظهر البديل والقائمة. إزالة المنع وإعادة تحميل الصفحة من الزر استعادا الخريطة مع بقاء الاختيار؛ لم يدّع الزر الاحتفاظ بنتيجة جولة في الذاكرة.

**تصحيح نصي بعد المتصفح:** كشف فحص ملف بإحداثيات ناقصة عبر استجابة محاكاة اختلاف العبارة عن المطلوب. صُححت إلى «لم يتم تحديد موقع العيادة بعد.» وتحققت مطابقتها في وحدة الملف المرسلة فعليًا من خادم التطوير. **لم تُعد هذه الحالة في المتصفح بعد تصحيح النص**؛ لا تُحسب إعادة اختبار متصفح ناجحة.

بعد إغلاق صفحة الاختبار أُزيل طبيبا الاختبار فقط، داخل معاملة تتحقق من الأسماء والمنطقة وعدم وجود أي سجل مرتبط بهما. عادت الأعداد إلى9 أطباء و3 منتجات؛ طابقت بصمات الأطباء والمنتجات والتقارير وملاحظات الصيدليات والزيارات المعلقة وجلسات العرض خط الأساس تمامًا. لم تُسترجع نسخة فوق بيانات المستخدم ولم تُعدّل سجلاته لإصلاح الخريطة.

## حدود معروفة

- البلاطات خدمة خارجية تتطلب الإنترنت وتخضع لسياسة وتوفر OpenStreetMap، وليست خرائط دون اتصال. عدم توفرها لا يُستبدل بصورة خريطة ثابتة.
- لا تجميع آلي للعلامات المتراكبة؛ استخدم التقريب أو الفلاتر أو قائمة الأطباء.
- البحث مطابقة جزئية للاسم، لا تطبيع شامل لاختلافات الهمزات والحروف.
- أداة إضافة الطبيب القائمة ما زالت تطلب موقعًا وأوقاتًا صالحة، ولم تُلغَ قيودها لزرع أمثلة ناقصة. مسار قراءة الخريطة يعالج البيانات القديمة غير الصالحة إن وجدت.
- لا حفظ دائم للجولات ولا صلاحيات إنتاجية جديدة. تظل أدوار المشرف والمندوب محاكاة عامة كما كانت.
- اختيار الجولة محفوظ لهذه التبويبة فقط، ويُمسح عند تبديل منظور المندوب؛ لا ينتقل اختيار مندوب إلى آخر.
- لم تُنفّذ حركة مرور أو ملاحة طرق أو اختبار تحميل وإنتاج أو نشر تلقائي.
